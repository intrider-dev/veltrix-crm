# Архитектура мультиязычности

В VeltrixCRM разделены три независимых уровня: системный интерфейс продукта, языковые предпочтения пользователя и переводимый контент рабочего пространства. Благодаря этому обновление приложения не перезаписывает шаблоны клиента, а смена языка одного пользователя не меняет данные всей команды.

## Как выбирается язык

| Уровень                              | Источник                      | Порядок выбора                                                 |
| ------------------------------------ | ----------------------------- | -------------------------------------------------------------- |
| Интерфейс и системные security-email | Версионируемые каталоги RU/EN | язык пользователя → язык workspace → язык deployment (`en`)    |
| Даты, числа и деньги                 | Нативный `Intl`               | язык пользователя + IANA timezone workspace                    |
| Шаблоны и сообщения workspace        | PostgreSQL-таблицы под RLS    | опубликованный перевод → перевод по умолчанию → исходный текст |

Введённые пользователем контакты, заметки, активности, custom fields и импортированные значения автоматически не переводятся и не отправляются внешнему AI-провайдеру.

## Системные каталоги

Английский источник находится в `packages/i18n/source/en`, русский перевод — в `packages/i18n/locales/ru`. Каждый файл является отдельным lazy-loaded namespace. Команда `pnpm generate:i18n` проверяет совпадение ключей и плейсхолдеров, а затем создаёт типизированный список ключей, JSON assets Angular и Go-каталог для ошибок API и системных email.

Добавление сообщения:

1. Добавить стабильный смысловой ключ в английский namespace.
2. Добавить тот же ключ во все локали.
3. Сохранить именованные плейсхолдеры вроде `{count}` без переименования.
4. Выполнить `pnpm generate:i18n`, `pnpm check:i18n`, `pnpm i18n:extract` и `pnpm test:web`.

Добавление языка:

```bash
pnpm i18n:add-locale --locale pt-BR --name "Português (Brasil)"
```

Скрипт проверяет BCP 47 tag, определяет LTR/RTL, создаёт все namespace, обновляет manifest и централизованную конфигурацию продукта. Все `⟦TODO⟧` нужно перевести: quality gate не пропустит незавершённую локаль.

## Настройки

Язык пользователя сохраняется сервером через `PATCH /api/v1/me`. Workspace хранит язык по умолчанию, список разрешённых языков и timezone. Настройки обновляются с ETag/version, поэтому параллельное редактирование не приводит к тихой потере данных. UI немедленно меняет язык, `<html lang>` и направление текста.

## Переводимый контент workspace

Центр переводов `/settings/translations` управляет шаблонами и сообщениями конкретного workspace. У ресурса есть namespace, стабильный key, исходный язык и текст, подсказка переводчику и список плейсхолдеров. У каждого перевода отдельные status `missing` / `draft` / `published` и version.

Гарантии:

- tenant isolation обеспечивается application guards и PostgreSQL RLS;
- размеры, locale, namespace и key ограничены и валидируются;
- набор плейсхолдеров обязан совпадать;
- cursor привязан к текущим фильтрам;
- `If-Match` защищает от потери параллельных изменений;
- audit/outbox не копируют текст перевода;
- в доставку попадает только опубликованный контент;
- coverage показывает незавершённые namespace.

Системные password-reset email нельзя переопределить tenant-контентом. Рендеринг отклоняет неразрешённые плейсхолдеры и переносы строк в теме письма.

Перед выпуском новой локали нужно проверить переключение и перезагрузку в браузере, axe для основных маршрутов, длинные подписи на трёх viewport и отдельный RTL-check при необходимости.
